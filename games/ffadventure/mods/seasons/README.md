# Seasons

A four-season system for ffadventure, tied to the in-game calendar.

Autumn browns the grass and turns deciduous canopies gold; winter drops the
temperature far enough that snow falls, settles and stays; spring melts it and
greens everything back up; summer runs lush and warm. Player body temperature
follows, so seasons are a survival concern rather than a paint job.

## Design

The game already had every ingredient — it just had nothing joining them up.
This mod supplies one number, a seasonal heat offset, and lets the existing
systems do the work they were already built to do.

| System | What it already did | What we change |
|---|---|---|
| `climate_api` / `regional_weather` | Gates snowfall, snow melt, river ice and rain-vs-snow entirely on `heat` | Wrap `environment.get_heat`, re-register the `heat` influence |
| `always_greener` | Runs an ABM repainting every grass node from a 16×16 palette | Wrap `awg.get_biome_color` |
| `tempsurvive` | Derives body temperature from biome heat | Wrap `tempsurvive.get_bio_temperature` |
| `dtrees` | Canopy nodes with a completely unused `param2` | Add a colour palette, repaint `param2` |
| `farming` | Probabilistic per-tick growth gate | Wrap the two growth entry points |

Only one file outside this mod is edited: three lines in
`always_greener/scripts/mapcolors.lua`, which reads the grass bias over IPC
because it runs in the isolated mapgen Lua environment. It falls back to
neutral when this mod is absent.

## Why leaves are tinted, not swapped

`dtrees` growth is an ABM cellular automaton whose entire state is the node
*name* and the spatial arrangement. `dt_apple_tree_growth.lua` alone contains
155 literal comparisons against `"apple_tree_canopy_base"`. Swapping a canopy
for a differently-named autumn variant would permanently stall trunk growth,
stop canopy spread, and leave a sapling planted in autumn unable to ever become
a tree.

So node names never change. `param2` is tinted instead — which is free, because
no dtrees growth file reads or writes `param2`, canopies declare no `paramtype2`
and no palette, and dtrees stores no node metadata or timers at all. Groups are
untouched, so `tree_felling`, leaf decay, `x_farming`'s apple and cocoa spawners
and the snow-cover ABM all keep working unchanged.

Palette index **0 is each species' summer colour**, because every dtrees
`set_node` call omits `param2` — which forces it to 0. Leaves therefore appear
at index 0 in every season, and must not look broken between repaints.

Textures are generated by `tools/gen_leaf_assets.py`. A Luanti palette
*multiplies* the tile, so the base tile is a pre-baked bright greyscale: the
shipped textures are far too dark to desaturate at runtime (apple's HSL
lightness peaks at 64 while its green channel reaches 127, and multiply can only
darken).

Note that `dtrees` ships **aspen already gold**, so it currently looks autumnal
in midsummer. This mod gives it a proper summer green and lets it reach roughly
its shipped gold at peak autumn.

## Commands

At 90 in-game days per season — around 30 real hours — `/season set` is the only
practical way to see or test any of this.

| Command | Privilege | Effect |
|---|---|---|
| `/season` | — | Season, date, warmth, foliage, and the heat offset where you stand |
| `/season set <spring\|summer\|autumn\|winter>` | `seasons` | Jump to the middle of a season |
| `/season skip <days>` | `seasons` | Advance by N in-game days |
| `/season reset` | `seasons` | Clear the offset |

## Tuning

`seasons_heat_amplitude` (default 22) and `seasons_tempsurvive_scale`
(default 0.35) are deliberately separate.

Amplitude drives the *world*. Lowering it to soften winter would break the
headline feature: at amplitude 18 a temperate biome lands at heat 36 in winter,
just above the `max_heat = 35` snow threshold, and it simply stops snowing.

`tempsurvive_scale` drives *player suffering*, and is the right lever for making
winter gentler or harsher.

## API

```lua
seasons.get_season()            -- "spring"|"summer"|"autumn"|"winter", day_in, days_left
seasons.get_day_of_year()       -- 0 .. YEAR_DAYS, fractional
seasons.get_warmth()            -- -1 (midwinter) .. +1 (midsummer)
seasons.get_foliage()           -- 0 (full green) .. 1 (bare/brown)
seasons.get_foliage_stage(pos)  -- 0..31, biome-gated and jittered per mapblock
seasons.get_heat_offset(pos)    -- signed engine heat units
seasons.crop_growth_factor(pos) -- growth multiplier
seasons.get_day_offset() / seasons.set_day_offset(n)
seasons.register_on_season_change(function(new, old) end)
seasons.YEAR_DAYS, seasons.SEASON_DAYS
```

`climate_api` users additionally get the influences `season`, `season_warmth`
and `season_phase`, so any weather preset can say `has_season = {"winter"}` or
`not_season = {"summer"}`.

The mapgen environment can read `core.ipc_get("seasons:season")` and
`core.ipc_get("seasons:grass_hum_delta")`.
